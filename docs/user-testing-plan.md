# 3-5人真实用户测试计划

**尚未执行。没有访谈原话、满意度、节省时间或效率提升结果。**

招募3-5名有GitHub课程团队经历的同学，至少包含一名组长、一名维护者和一名经验较少的贡献者。先告知AI辅助建议、合成数据、观察记录用途，可随时退出。默认用Mock仓库，不收集PAT；不得用真实课程/私有项目内容直接送第三方模型。

每人30-40分钟，使用交叉顺序避免所有人先熟悉同一个流程。先用网页/文本模拟手工任务，再用工作台处理难度匹配的任务，顺序在参与者间轮换。

| 任务 | 观察 | 记录 |
| --- | --- | --- |
| 判断缺少什么信息 | 是否找到复现/环境/预期结果 | 时间、遗漏项、人工修改 |
| 检查标签和回复提案 | 是否理解具体repo/Issue/正文 | 复述是否正确、误批准数 |
| 拒绝一条不合适回复 | 是否找到拒绝，是否误以为已经执行 | 点击路径、恢复时间 |
| 处理限流/无模型 | 是否识别MOCK/OFFLINE及停止状态 | 模式误解次数 |
| 检查UNKNOWN写入 | 是否知道不能盲目重复执行 | 是否提出核对GitHub |

记录表字段：匿名编号、经验范围、任务ID、顺序、开始结束时间、是否独立完成、错误、审批理解、采纳/修改/拒绝、原始观察、主观难度1-5。用户表达必须原文记录并匿名，不由AI填造。

成功判据暂定为：没有误批准；所有人能正确复述执行目标和正文；至少多数能独立完成只读与审批流程。任何未审批写入立即中止测试。小样本时间只作描述性比较，报告个体值和中位数，不推断总体显著提升。

访谈提问：你为什么批准/拒绝？哪项参数难理解？你相信OFFLINE结果到什么程度？为什么选这个任务而非Issue Forms？什么时候宁愿直接去GitHub？UNKNOWN时你会做什么？最终报告同时写出反例，不只挑选正面反馈。
